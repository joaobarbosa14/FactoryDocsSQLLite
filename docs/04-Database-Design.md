# Database Design

## Core Entities

### Documents
- `Id` — primary key
- `DocumentNumber` — unique business identifier
- `Title` — required title
- `Category` — category label for the MVP
- `Description` — optional description
- `Status` — lifecycle state
- `CreatedAtUtc` — creation timestamp

### Planned tables for the next iteration

- `Categories`: configurable categories.
- `DocumentRevisions`: revision number, file reference, change summary, author and timestamp.
- `Users`: application user identity and role mapping.
- `AuditLogs`: actor, action, entity, timestamp and details.

## Data Integrity

- `DocumentNumber` must be unique.
- Required fields must be validated in the API.
- Status values must be constrained to known values.
- Timestamps should be stored in UTC.
- Revision history should be append-only.
- Database constraints should complement, not replace, application validation.

## Example Query

```sql
SELECT Id, DocumentNumber, Title, Category, Status, CreatedAtUtc
FROM Documents
WHERE Status = 'Approved'
ORDER BY CreatedAtUtc DESC;
```


## Database provider strategy

The local development default is SQLite to make the MVP easy to run on macOS Apple Silicon without a database container. Entity Framework Core is configured through `DatabaseProvider` in `src/FactoryDocs.Api/Program.cs`. Set `DatabaseProvider=SqlServer` and configure `ConnectionStrings__FactoryDocs` to use a reachable Microsoft SQL Server instance. Keep schema changes provider-neutral where possible and validate both providers before deployment. The SQL Server reference schema in `database/reference-schema.sql` is a conceptual SQL Server-oriented reference; the running demo schema is generated by EF Core.
